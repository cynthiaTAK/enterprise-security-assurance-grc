# Publishing guide

1. Review every file for private information, employer names, internal screenshots, tokens and identifying details. This package contains curated fictional records only.
2. Sign in to GitHub and create a **public** repository named `enterprise-security-assurance-grc` (or choose private until reviewed).
3. Upload the **contents of this folder**, keeping the directory structure. GitHub will display `README.md` on the repository homepage.
4. Add repository description: `Simulated GRC portfolio: customer security assurance, SOC 2 evidence coordination, access reviews, exception management and remediation validation.`
5. Optional topics: `grc`, `soc2`, `cybersecurity`, `audit`, `iam`, `risk-management`, `security-assurance`.
6. Check all Markdown links and CSV previews on GitHub. Do not publish the original full workbook unless you have separately reviewed every cell and metadata field.
7. Add the repository link to your résumé under Projects and to LinkedIn's Featured section.

**Optional git command-line route** (run locally from this directory after creating the empty repository):
```bash
git init
git add .
git commit -m "Publish simulated GRC security assurance portfolio"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/enterprise-security-assurance-grc.git
git push -u origin main
```
Replace `YOUR-USERNAME` with your GitHub username. This package has not been published automatically.
